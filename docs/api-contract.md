# API-контракт UniPlan (TSK-04)

Базовый адрес — тот же, что у клиента (`http://localhost:3000`). Все запросы и ответы — JSON в UTF-8.
Авторизация — cookie `uniplan_sid` (HttpOnly, SameSite=Lax), выдаётся при входе или регистрации и живёт 30 дней.

## Формат ошибок

```json
{ "error": "Проверьте поля формы", "details": [{ "path": "login", "message": "Логин: 3–32 символа…" }] }
```

`details` есть не всегда. `path` указывает на поле формы (`login`) или элемент файла (`lessons[3].start`).

| Код | Когда |
|-----|-------|
| 400 | Некорректные поля или параметры |
| 401 | Не выполнен вход / неверный логин или пароль |
| 403 | Действие доступно только старосте |
| 404 | Объект не найден или принадлежит другому пользователю или группе |
| 409 | Конфликт: логин занят, пара пересекается с другой |
| 413 | Тело запроса больше 1 МБ |
| 422 | JSON-файл расписания не прошёл проверку |

## Модели

**User** — `{ id, login, name, role: "student" | "starosta", groupId }`
**Group** — `{ id, name, semesterStart: "ГГГГ-ММ-ДД" }`; в ответах `/api/auth/*` и `/api/me` ещё `starostas: [имена старост группы]`
**Lesson** — `{ id, day: 1–7, week: 0 | 1 | 2, start: "ЧЧ:ММ", end: "ЧЧ:ММ", subject, type, room, teacher }`
  `week`: 0 — каждую неделю, 1 — только I, 2 — только II.
  `type`: `лекция`, `практика`, `лабораторная`, `семинар`, `другое`.
**Task** — `{ id, date: "ГГГГ-ММ-ДД", text, subject: string | null, done: boolean }`

## Тип недели

Неделя (пн–вс), в которую попадает `semesterStart` группы, — I. Дальше недели чередуются.
Та же функция используется на клиенте: `shared/week.js`.

## Эндпоинты

### Справочники

| Метод | Путь | Доступ | Ответ |
|-------|------|--------|-------|
| GET | `/api/groups` | все | `{ groups: [{ id, name }] }` |
| GET | `/api/meta` | все | `{ demo: boolean, lessonTypes: [...] }` |

### US-01. Регистрация, вход, профиль

| Метод | Путь | Тело | Ответ |
|-------|------|------|-------|
| POST | `/api/auth/register` | `{ name, login, password, groupId }` | 201 `{ user, group }` + cookie |
| POST | `/api/auth/login` | `{ login, password }` | 200 `{ user, group }` + cookie · 401 |
| POST | `/api/auth/demo` | `{ as: "student" \| "starosta" }` | 200 `{ user, group }` (только при `DEMO≠0`) |
| POST | `/api/auth/logout` | — | 204 |
| GET | `/api/me` | — | `{ user, group }` |
| PATCH | `/api/me` | `{ name?, groupId? }` | `{ user, group }` · 403 — староста не меняет группу |

Роль при регистрации всегда `student`; старосту назначает администратор командой `npm run manage -- role <логин> starosta`.

Правила полей регистрации: имя — от 2 до 60 символов; логин — `[a-zA-Z0-9_.-]{3,32}`, без учёта регистра;
пароль — от 6 символов. Пароли хранятся как scrypt-хэш с солью.

### US-02. Расписание

| Метод | Путь | Ответ |
|-------|------|-------|
| GET | `/api/schedule?week=1\|2&day=1..7&groupId=` | `{ group, lessons }` — без параметров: все пары группы пользователя |
| GET | `/api/week-type?date=ГГГГ-ММ-ДД` | `{ date, monday, week, semesterStart }` |

С параметром `week=1` возвращаются пары с `week` 0 и 1.

### US-04. Ручной ввод (только староста, своя группа)

| Метод | Путь | Тело | Ответ |
|-------|------|------|-------|
| POST | `/api/lessons` | Lesson без `id` | 201 `{ lesson }` · 409 при пересечении |
| PUT | `/api/lessons/:id` | Lesson без `id` | 200 `{ lesson }` |
| DELETE | `/api/lessons/:id` | — | 204 |
| PATCH | `/api/group` | `{ semesterStart }` | `{ group }` |

Пары пересекаются, если они в один день, у них есть общая неделя и интервалы времени накладываются.

### US-05. Импорт и экспорт JSON

| Метод | Путь | Тело | Ответ |
|-------|------|------|-------|
| POST | `/api/schedule/import` | `{ data, mode: "replace" \| "append", dryRun?: true }` | 200 `{ imported, mode, summary, group }` · 422 `{ error, details }` |
| GET | `/api/schedule/template` | — | шаблон файла (скачивание) |
| GET | `/api/schedule/export` | — | текущее расписание группы в формате файла |

При `dryRun: true` файл только проверяется: ответ `{ dryRun, mode, summary, lessons, semesterStart }`, база не меняется.
В режиме `append` пары из файла дополнительно проверяются на пересечение с уже существующими.

### US-03. TODO-лист дня

| Метод | Путь | Тело | Ответ |
|-------|------|------|-------|
| GET | `/api/tasks?date=` или `?from=&to=` | — | `{ tasks }` — только задачи текущего пользователя |
| POST | `/api/tasks` | `{ date, text, subject? }` | 201 `{ task }` |
| PATCH | `/api/tasks/:id` | `{ done?, text? }` | `{ task }` |
| DELETE | `/api/tasks/:id` | — | 204 |

Текст задачи — от 1 до 200 символов. Чужая задача — 404.

## Формат JSON-файла расписания

Пример — [`schedule-template.json`](schedule-template.json), полное расписание группы — [`schedule-example.json`](schedule-example.json).

```json
{
  "group": "25ИП3б",
  "semesterStart": "2026-09-01",
  "lessons": [
    { "day": "Пн", "week": "обе", "start": "08:00", "end": "09:30",
      "subject": "Базы данных", "type": "лекция", "room": "7-305", "teacher": "Зайцев К.В." }
  ]
}
```

| Поле | Обязательно | Значения |
|------|-------------|----------|
| `group` | нет | если указано, должно совпадать с группой старосты |
| `semesterStart` | нет | `ГГГГ-ММ-ДД`; если указано, обновляет начало семестра |
| `lessons` | да | массив, от 1 до 300 пар |
| `lessons[].day` | да | 1–7 или `Пн`…`Вс`, `понедельник`…, `mon`… |
| `lessons[].week` | нет (по умолчанию «обе») | `1`, `2`, `"I"`, `"II"`, `"обе"`, `0` |
| `lessons[].start`, `end` | да | `ЧЧ:ММ` или `Ч:ММ`; `end` позже `start` |
| `lessons[].subject` | да | до 120 символов |
| `lessons[].type` | нет (по умолчанию «другое») | `лекция`, `практика`, `лабораторная` (`лаба`, `лр`), `семинар`, `другое` |
| `lessons[].room` | да | до 40 символов |
| `lessons[].teacher` | нет | до 80 символов |

Можно загрузить и просто массив пар без обёртки — он будет воспринят как `lessons`.
